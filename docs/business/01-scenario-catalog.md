## 1. シナリオ概要

| 項目 | 値 |
|---|---|
| シナリオ総数 | 12 |
| 正常系 | 8 |
| 異常系 | 4 |
| 想定時間 | 各シナリオ 30 分 - 2 時間 |
| アクター | 田中（営業）、鈴木（データ）、佐藤（IT）、山田（SRE） |

## 2. 業務カテゴリ別シナリオ

### 2.1 営業シナリオ

| ID | シナリオ名 | 関連 F-ID | 概要 |
|---|---|---|---|
| SCN-01 | 売上リアルタイムダッシュボード | F-15, F-01 | 売上変更を 1 秒以内にダッシュボード反映 |
| SCN-02 | キャンペーン効果分析 | F-04, F-01 | キャンペーン前後の売上比較 |
| SCN-03 | 部門間データ共有 | F-11 | 営業部門とマーケティング部門で画布共有 |

### 2.2 データシナリオ

| ID | シナリオ名 | 関連 F-ID | 概要 |
|---|---|---|---|
| SCN-04 | 新しいデータソース追加 | F-02, F-07 | 1 週間以内に新規 DB 連携を追加 |
| SCN-05 | 複雑な変換ロジック実装 | F-04, F-05, F-06 | 100 ステップの ETL を 1 日で実装 |
| SCN-06 | 既存 Python 資産の流用 | F-07 | プラグインとして既存ロジックを統合 |

### 2.3 IT シナリオ

| ID | シナリオ名 | 関連 F-ID | 概要 |
|---|---|---|---|
| SCN-07 | 新規テナント開設 | F-17, F-11 | 1 営業日以内にテナント開設 |
| SCN-08 | 権限管理 | F-11, F-17 | ロール・属性で柔軟に権限設定 |

### 2.4 SRE シナリオ

| ID | シナリオ名 | 関連 F-ID | 概要 |
|---|---|---|---|
| SCN-09 | インシデント発生時の対応 | F-15 | 30 分以内に初動、復旧 |
| SCN-10 | リリース + ロールバック | F-15, F-17 | 5 分以内の切替、ロールバック |

## 3. 異常系シナリオ

| ID | シナリオ名 | 概要 | 期待動作 |
|---|---|---|---|
| ABN-01 | データソース接続失敗 | 業務 DB がダウン | 自動リトライ + アラート + グレースフルデグレード |
| ABN-02 | 大量データ流入 | 100 万件 / 分のスパイク | バックプレッシャー + スケールアウト |
| ABN-03 | 認証失敗 | 不正トークン | 401 + 監査ログ + 通知 |
| ABN-04 | テナント越境試行 | 悪意あるアクセス | 403 + 監査ログ + SecO 通知 |

## 4. シナリオ適合性

| シナリオ | 業務適合性 | 期待効果 |
|---|---|---|
| SCN-01 売上リアルタイム | 高 | 経営判断速度 24h → 1s |
| SCN-02 キャンペーン効果 | 高 | ROI 把握 1 週 → 1 時間 |
| SCN-03 部門間共有 | 中 | コラボレーション向上 |
| SCN-04 新規ソース | 高 | 構築期間 1-2 ヶ月 → 1 週 |
| SCN-05 複雑な ETL | 高 | 構築期間 2 週 → 1 日 |
| SCN-06 Python 流用 | 中 | 既存資産活用 |
| SCN-07 テナント開設 | 必須 | オンボーディング 1 日 |
| SCN-08 権限管理 | 必須 | セキュリティ + 柔軟性 |
| SCN-09 インシデント | 必須 | MTTR 4h → 30min |
| SCN-10 リリース | 必須 | 切替 30min → 5min |
| ABN-01 接続失敗 | 必須 | 業務継続性 |
| ABN-02 大量流入 | 高 | スケーラビリティ |
| ABN-03 認証失敗 | 必須 | セキュリティ |
| ABN-04 越境試行 | 必須 | セキュリティ |
