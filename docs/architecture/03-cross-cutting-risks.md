## 1. 概要

本表汇集影响多个模块、不归属任何单一模块的横切风险。每项风险标注 NF 等级（必須/推奨），便于追溯到 ST 验收用例的 P0/P1 级别。各模块内部细节风险保留在各自模块文件中。

## 2. 业务与合规风险

| リスクID | リスク内容 | 影响度 | 応对方針 | 涉及模块 | NF タグ |
|---|---|---|---|---|---|
| R-01 | 目标平台页面结构变更导致选择器失效 | 高 | 实现 F-12 自愈提示机制；提供选择器健壮性建议 | M-01, M-04 | [NF-AVA]【必須】 |
| R-02 | 平台反爬策略升级导致采集被封禁 | 高 | 限流、随机化访问节奏、明确合规使用边界 | M-01 | [NF-SEC]【必須】 |
| R-03 | 无限画布节点规模过大导致前端卡顿 | 中 | 引入虚拟化渲染（视口裁剪）、分组折叠 | M-12 | [NF-PER]【必須】 |
| R-04 | 用户凭证泄露 | 高 | 本地加密存储、避免凭证经过第三方服务器中转 | M-01, M-10 | [NF-SEC]【必須】 |
| R-05 | 法律合规风险（数据抓取相关法规） | 高 | 产品层面明确免责声明与合规指引 | M-01 | [NF-SEC]【必須】 |

## 3. 多租户与安全风险

| リスク | 影响度 | 応対方案 | 涉及模块 | NF タグ |
|---|---|---|---|---|
| 多租户某个大计算任务（Playwright 采集）耗尽共享资源 | 高 | 实现严格的配额隔离、Kubernetes 资源限制、优先级队列 | M-10, M-01 | [NF-PER]【必須】 |
| 数据库行级安全（RLS）配置错误导致租户数据穿透 | 严重 | 定期安全审计、多租户穿透测试、应用层"双重检查" | M-10 | [NF-SEC]【必須】 |
| Playwright 采集过程中浏览器崩溃导致租户挂起 | 中 | 进程监控重启、自动故障转移、用户可手动中止执行 | M-01, M-05 | [NF-AVA]【必須】 |

## 4. 前端与性能风险

| リスク | 影响度 | 応対方案 | 涉及模块 | NF タグ |
|---|---|---|---|---|
| 编排引擎状态序列化/反序列化性能问题 | 中 | 增量状态存储、异步序列化、分片存储 | M-04 | [NF-PER]【必須】 |
| bevy_egui 中文输入法（IME）支持不成熟 | 高 | 混合渲染策略，HTML Overlay 承载中文输入 | M-12 | [NF-OPS]【必須】 |
| Bevy WASM 包体积偏大，首屏加载时间长 | 中 | 裁剪未使用 feature、启用 `wasm-opt`、显示加载进度条 | M-12 | [NF-ENV]【必須】 |
| Bevy 生态成熟度低于 React 生态 | 中 | 团队需具备 Rust 全栈能力、保留 React 备选方案 | M-12 | [NF-MIG]【推奨】 |

## 5. 验收硬指标

来自 [requirements §12](../legacy/requirements.md)：

1. 能够在无官方 API 的示例平台上，通过可视化点选方式在 **10 分钟内**配置完成一个采集节点，并成功采集并标准化至少 1 条数据。 [NF-OPS]【必須】
2. 画布可完成"采集 → 转换 → 条件路由 → 输出至本地文件"的端到端流程搭建与执行。 [NF-OPS]【必須】
3. Runtime 在三大操作系统（Windows/macOS/Linux）上均可实现免安装启动。 [NF-MIG]【必須】
4. 单画布 **1,000 节点**规模下，前端交互（拖拽/缩放/连线）保持流畅（不低于 **30fps**）。 [NF-PER]【必須】
5. 编排引擎能正确执行条件分支、循环、异常重试三类基础控制逻辑。 [NF-AVA]【必須】
6. 系统在采集节点配置界面明确展示合规使用提示文案。 [NF-SEC]【必須】
