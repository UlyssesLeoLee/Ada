## 1. 概要

为使系统在节点数量与业务复杂度增长时仍保持**可推理性**与**可维护性**，本系统采用生物仿生学分层架构，将系统职责映射为生物体的四层结构。这是所有模块（[docs/modules/](../modules/)）共同遵循的总纲。

## 2. 生体類比 → システム要素 映射

| 生体類比 | 対応するシステム要素 | 職責 |
|---|---|---|
| **骨格** | 节点（Node） | 提供结构性支撑，定义"是什么"——即每个处理单元的静态能力（输入/输出 schema、参数配置、执行逻辑）。骨格本身不主动运动，仅被驱动。 |
| **血液（データフロー）** | データフロー（Data Flow） | 不受"神经"（编排引擎）的直接强控制，仅依据既定的流转路径（血管，即连线）持续、自主地在节点间搬运标准化 JSON 数据包，类似循环系统的自主调节。 |
| **神经系统（LangGraph）** | 编排引擎（Orchestration Engine） | 感知状态、做出决策：条件判断、状态迁移、循环/中断、异常捕获与重试策略。 |
| **筋肉（制御フロー）** | 制御フロー（Control Flow） | 神经系统下达的指令被转化为具体的"动作"——即节点的实际触发、暂停、跳过、并行/串行调度。 |

## 3. アーキテクチャ分层示意

```
┌─────────────────────────────────────────────┐
│  前端表现层：无限画布 Web UI（类 Miro）        │
│  节点拖拽 / 连线编辑 / 实时预览 / 调试面板      │
└───────────────────┬───────────────────────────┘
                     │ 画布配置（DAG/StateGraph 定义）
┌───────────────────▼───────────────────────────┐
│  神经系统层：编排引擎（LangGraph 风格状态机）    │
│  状态感知・条件决策・异常与重试策略・循环控制    │
└───────────────────┬───────────────────────────┘
                     │ 调度指令
┌───────────────────▼───────────────────────────┐
│  肌肉层：控制流执行器（Control Flow Executor）  │
│  节点触发・并发调度・暂停恢复・限流退避          │
└───────────────────┬───────────────────────────┘
                     │ 驱动
┌───────────────────▼───────────────────────────┐
│  骨骼层：节点运行时（Node Runtime，骨骼各单元） │
│  采集适配器节点 / 转换节点 / 路由节点 / 输出节点 │
└───────────────────┬───────────────────────────┘
                     │ 生成/消费
┌───────────────────▼───────────────────────────┐
│  血液层：标准化数据流总线（NJSON Data Bus）      │
│  在节点间沿"血管"（连线）持续搬运标准化 JSON     │
└───────────────────┬───────────────────────────┘
                     │ 采集
┌───────────────────▼───────────────────────────┐
│  外部环境层：Playwright 浏览器自动化采集层       │
│  面向无 API 平台的 DOM 抓取・标准化转换          │
└─────────────────────────────────────────────┘
```

## 4. 設計原則

1. **数据流与控制流解耦** — 数据流的"血液"具备一定的自主流转特性（如数据在连线上可被缓存、限速、重放），不必每一次流转都经过神经系统层的显式决策。 [NF-PER]【必須】
2. **神经系统只做决策，不做体力劳动** — 编排引擎（LangGraph 层）只负责状态判断与路径选择，实际的节点执行与并发调度下放给控制流（肌肉）层。 [NF-OPS]【必須】
3. **骨骼可插拔** — 节点作为最小单元，支持插件化扩展。 [NF-OPS]【必須】
4. **足够底层，足够智能** — 底层指 Runtime 直接操作浏览器渲染层（DOM/网络层），不依赖平台方 API；智能指编排引擎具备基于 LLM/规则的语义级决策能力。 [NF-AVA]【必須】

## 5. 多租户与底层智能平衡（基本设计坚守要点）

- **生体仿生架构坚守**：系统严格遵循上述四层职责划分。 [NF-OPS]【必須】
- **多租户优先设计**：无论单机本地模式还是 SaaS 部署模式，所有数据模型包含 `tenant_id` 字段，所有数据库查询/API 请求自动注入租户隔离条件。 [NF-SEC]【必須】
- **底层智能平衡**：底层直接操作浏览器渲染层（DOM/网络流量），无 API 场景下自动降级；智能层（编排引擎）支持 LLM 集成。 [NF-PER]【必須】
- **开发体验最优化**：用户应能通过可视化拖拽完成 80% 常见场景。 [NF-OPS]【推奨】

## 6. 与既存工具の差异化定位

| 比较项 | 传统 iPaaS（如 DataSpider） | 本系统 |
|---|---|---|
| 数据源前提 | 主要依赖已开放的 API/协议连接器，遇到无 API 平台即失效 | API 与无 API 场景通吃 |
| 部署方式 | 通常需要服务器安装与授权 | 免安装、前端网页化、Runtime 单文件分发 [NF-MIG]【必須】 |
| 编排模型 | 流程图式，控制与数据耦合 | 数据流与控制流分层解耦 |
| 扩展方式 | 厂商预置连接器为主 | 采集适配器/节点插件化 |
| 覆盖广度 | 以企业系统/数据库为主 | 企业系统与 IM/协作工具并重 |
