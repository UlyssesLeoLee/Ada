## 1. 概要

本書は `docs/` 配下すべての文書の標準形式を定める。  
新規文書を起案する際は、本書の構成に厳密に従うこと。  
既存文書を本書に合わせる作業（IPA 準拠化）の基準も本書に従う。

準拠する IPA 標準：

- **共通フレーム2018 (SLCP-JCF2018)** — 文書ライフサイクル・承認プロセス
- **非機能要求グレード** — 非機能要求の 6 大類 × 2 段階評価
- **ソフトウェア開発データ白書** — 文書メタデータ形式

## 2. 文档元信息（必須・每份文档头部必填）

### 2.1 フォーマット

每份文档の冒頭（タイトル直下）に以下を配置する：

```markdown
> **ドキュメントID**：[DOC-{大类}-{三位流水}]
> **文書分類**：[要件定義書 | 基本設計書 | 詳細設計書 | 単体テスト設計書 | 結合テスト設計書 | システムテスト設計書 | 横断文書]
> **バージョン**：v[主].[副].[订]
> **制定日**：YYYY-MM-DD
> **最終更新日**：YYYY-MM-DD
> **作成者**：[起草人 / 团队名]
> **レビュー**：[TBD / 实际审阅人]
> **承認**：[TBD / 实际批准人]
> **上位文書**：[path or 無]
> **下位文書**：[path or 無（複数行可）]
> **関連文書**：[path list（複数行可）]
> **適用 IPA 標準**：
> - IPA「共通フレーム2018」(SLCP-JCF2018)
> - IPA「非機能要求グレード」(該当する場合)
> - IPA「ソフトウェア開発データ白書」
> **機密区分**：[公開 | 社内 | 社外秘]
> **言語**：[中文（简体）]
```

### 2.2 起草/レビュー/承認 の扱い

- 確定前は `TBD` を記入する
- 確定後、起草/レビュー/承認の3 ロール全て記入する
- 改訂のたびに「改訂履歴」テーブルを更新する

## 3. 文档 ID 命名规则

| 大类 | プレフィックス | 例 | 対象文書 |
|---|---|---|---|
| 索引/総覧 | `DOC-INDEX` | DOC-INDEX-001 | README.md |
| 変更履歴 | `DOC-CHG` | DOC-CHG-001 | CHANGELOG.md |
| テンプレート | `DOC-TPL` | DOC-TPL-001 | template.md |
| 要件定義書 | `DOC-REQ` | DOC-REQ-001 | legacy/requirements.md |
| 基本設計書 | `DOC-BSC` | DOC-BSC-001 | legacy/basic-design.md |
| 詳細設計書 | `DOC-DTL` | DOC-DTL-001 | legacy/detailed-design.md |
| 横断文書（architecture） | `DOC-ARCH` | DOC-ARCH-001 | architecture/00-anatomy-model.md |
| モジュール別設計書 | `DOC-MOD` | DOC-MOD-001 (= M-01) | modules/M-01-acquisition-adapter.md |
| API/インタフェース仕様 | `DOC-API` | DOC-API-001 | api/rest-endpoints.md |
| テスト設計書 | `DOC-TST` | DOC-TST-001 | tests/UT-design.md |
| 受入テスト設計書 | `DOC-ACC` | DOC-ACC-001 | tests/ST-design.md（受入部分） |

命名规则：

- 半角英大文字・数字・ハイフンのみ
- `{大类}` と `{流水}` の区切りは `-`
- 流水は 3 桁ゼロパディング（001, 002, ...）

## 4. 改訂履歴（必須）

フォーマット：

```markdown
## 改訂履歴

| バージョン | 日付 | 変更内容 | 起草 | レビュー | 承認 |
|---|---|---|---|---|---|
| v1.0.0 | YYYY-MM-DD | 初版制定 | [起草] | [レビュー] | [承認] |
| v1.0.1 | YYYY-MM-DD | [変更内容] | [起草] | [レビュー] | [承認] |
```

- バージョン番号は Semantic Versioning に従う
  - 主番号：内容に大きな構造変更（章立て改編等）
  - 副番号：内容の追加・削除
  - 訂番号：誤字・誤記の修正
- 日付は ISO 8601（YYYY-MM-DD）

---

## 5. 目次（必須）

フォーマット：

```markdown
## 目次

1. [章名]
2. [章名]
   1. [節名]
   2. [節名]
3. ...
```

- 階層は `1`, `1.1`, `1.1.1` の三段まで
- 4 段以上は推奨しない（深すぎる章立ては読み手の認知的負荷を高める）
- 目次は本文の実体と完全一致を保つ

---

## 6. 本文（必須）

- 各章は `## N. [章名]` 形式
- 節は `### N.M [節名]` 形式
- 項は `#### N.M.K [項名]` 形式
- 図表は `表 N-M-N` `図 N-M-N` 形式で番号付与
- コードブロックは ```rust / ```sql / ```typescript / ```json 等、言語タグ必須
- 章番号は連番（飛び番禁止）
- 章タイトルは簡潔に（目安：15 文字以内）

## 7. 用語集（必須）

フォーマット：

## 用語集

| 用語 | 説明 | 出典 / 参照 |

- 出典/参照は節番号 or 外部文献リンク

## 9. 非機能要求グレード タグ規約（該当する場合必須）

非機能要求に該当する項目には、項目末尾に次のタグを付与する：

```markdown
[NF-{分类}]【{等级}】
```

### 9.1 分類（6 大類、IPA「非機能要求グレード」に準拠）

| タグ | 分類 | 英語表記 | 例 |
|---|---|---|---|
| `[NF-AVA]` | 可用性 | Availability | 7×24 時間連続稼働 |
| `[NF-PER]` | 性能・拡張性 | Performance / Scalability | 1000 ノードで 30fps |
| `[NF-OPS]` | 運用・保守性 | Operability / Maintainability | 構造化ログ |
| `[NF-MIG]` | 移行性 | Portability / Migration | Win/macOS/Linux 対応 |
| `[NF-SEC]` | セキュリティ | Security | 凭证加密存储 |
| `[NF-ENV]` | システム環境・エコロジー | System Environment / Ecology | 4 核 8GB 起動 |

### 9.2 等級（2 段階）

| 等級 | 意味 | テストでの扱い |
|---|---|---|
| `【必須】` | 必須項目 | 受け入れ不可。テストの P0 相当 |
| `【推奨】` | 推奨項目 | 協議可。テストの P1 相当 |

### 9.3 適用例

```markdown
| 項目 | 要求水準 |
|---|---|
| システム运行持续性 | Runtime 应支持长时间（≥7×24 小时）稳定运行 [NF-AVA]【必須】 |
| 插件热更新 | 节点插件更新后无需重启整个 Runtime 即可生效 [NF-OPS]【推奨】 |
```
