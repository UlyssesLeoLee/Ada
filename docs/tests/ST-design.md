## 0. 通用约定

- **测试框架**：
  - E2E：Playwright + 自研验收脚本（Python/TypeScript）
  - 性能：`k6` 或 `wrk` 做压测
  - 安全：OWASP ZAP / 静态扫描 `cargo audit` / `trivy`
  - 兼容：虚拟机矩阵（Windows/macOS/Linux）× Chrome/Edge/Safari/Firefox
- **环境**：预生产环境（与生产配置一致）
- **入口条件**：所有 IT 用例通过 + 预生产环境就绪 + 测试数据准备完成
- **出口条件**：100% 用例执行 + P0/P1 全通过 + 非功能指标达标 + 验收硬指标全部满足
- **测试数据**：使用 `seed/` 脚本生成包含测试租户、用户、画布的初始数据
- **可观测性**：所有 ST 用例触发后，自动收集 metrics/logs/trace 至 `st-run-{timestamp}/` 目录

## 7. 质量门禁

- **P0 用例通过率**：100%（任意 P0 失败阻塞发版）
- **P1 用例通过率**：100%（下个迭代必须修复）
- **验收硬指标**：ACC-001~ACC-008 全部通过
- **非功能指标**：NFR-001~NFR-029 全部达标
- **冒烟测试**：SMK-001~SMK-008 全部通过
- **覆盖率**：与 UT/IT 一致
- **可观测性**：所有失败用例必须附带 metrics/logs/trace 证据

## 8. 报告与签发

- 每次 ST 执行生成 `st-report-{timestamp}.html` 包含：
  - 用例执行结果
  - 性能指标（FPS、延迟、吞吐）
  - 资源占用曲线
  - 失败用例的 stack trace + 日志链接
- ST 通过后由 QA 负责人签发 [ST-passed.md](ST-passed.md)（单独文件，本轮不创建）
