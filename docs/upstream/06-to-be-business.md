## 1. 業務ビジョン

| 軸 | As-Is | To-Be |
|---|---|---|
| 主体 | データエンジニア | 業務部門 + データエンジニアの協働 |
| 頻度 | 日次バッチ | リアルタイム + バッチ ハイブリッド |
| 構築 | ETL ツール | ノーコードキャンバス |
| 監視 | 手動 | 自動 + 通知 |
| 復旧 | 手動 | 自動リトライ + ロールバック |
| コスト | 年 1,000 万円 | 0 円（OSS 化） |

## 2. 主要業務フロー

### 2.1 データ統合フロー（To-Be）

```
[業務システム A]                    [業務システム B]
   │                                    │
   │ REST API / Webhook              │ DB CDC
   ▼                                    ▼
[Acquisition Adapter]              [Acquisition Adapter]
   (M-01)                              (M-01)
   │                                    │
   │ リアルタイム Push                  │ CDC ストリーム
   ▼                                    ▼
[Normalizer]                      [Normalizer]
   (M-02)                              (M-02)
   │                                    │
   │ NJSON 標準化                       │
   ▼                                    ▼
[Data Flow Engine] ←──── ユーザー編集 ──────┐
   (M-03)                                    │
   │                                          │
   │ キャンバス上のノード実行                  │
   ▼                                          │
[中央イベントバス]                            │
   (M-15)                                     │
   │                                          │
   │ イベント駆動                              │
   ▼                                          │
[Orchestration] → [Trigger] → [Control Flow] │
   (M-04)    (M-08)     (M-05)               │
   │                                          │
   ▼                                          │
[Exporter] → 業務システム / ファイル / API     │
   (M-09)                                     │
                                              │
   ▲ ユーザー ▼ 編集                           │
   │                                          │
[Canvas Editor] ←────────────────────────────┘
   (M-12)
   - 視覚的 ETL 構築
   - リアルタイムプレビュー
```

### 2.2 業務フロー詳細

| # | タスク | アクター | システム | 所要時間 | 削減率 |
|---|---|---|---|---|---|
| 1 | データ要件定義 | 業務部門 | Canvas | 0.5 日 | 75% |
| 2 | ETL 設計 | 業務部門 + データ | Canvas + 自動推薦 | 1 日 | 75% |
| 3 | 実装 | 業務部門（ノーコード） | Canvas | 0.5 日 | 90% |
| 4 | 単体テスト | 自動 | 自動 UT | 自動 | 100% |
| 5 | 本番リリース | 1 クリック | atomic swap | 5 分 | 99% |
| 6 | 運用監視 | 自動 | ダッシュボード | 自動 | 100% |
| 7 | 障害対応 | 自動 + 通知 | 自動リトライ | 30 分 | 87% |

## 3. アクターと役割（To-Be）

| アクター | As-Is | To-Be | 変化 |
|---|---|---|---|
| 業務部門 | 要件・検証のみ | 構築・検証の主体 | 役割拡大 |
| データエンジニア | 構築・運用 | 高度化業務 + プラグイン開発 | 役割高度化 |
| IT 部門 | インフラ + 認証 | インフラ + セキュリティ | 不変 |
| マネージャー | 承認 | ガバナンス + KPI 監視 | 役割変化 |

## 4. 課題別解決策

| 課題 | To-Be 解決策 | 対応モジュール |

## 5. 業務量 / 効率目標

| 項目 | As-Is | To-Be | 改善率 |
|---|---|---|---|
| 新規 ETL 構築工数 | 10-15 日 | 1-2 日 | 85% |
| 業務部門関与 | 3-5 日/人 | 0.5 日/人 | 90% |
| リリース頻度 | 月 2-3 件 | 日 10+ 件 | 10x |
| MTTR | 4 時間 | 30 分 | 87% |
| 年間ライセンスコスト | 1,000 万円 | 0 円 | 100% |
| データ反映遅延 | 24 時間 | < 1 秒 | 99.99% |
| 属人数 | 2 名 | 分散化 | リスク解消 |

## 6. 業務適合性

| 業務部門 | 適合性 | 理由 |
|---|---|---|
| 営業 | 高 | CRM 連携でリアルタイム性向上 |
| マーケティング | 高 | キャンペーン即時反映 |
| 在庫管理 | 高 | リアルタイム在庫反映 |
| 経理 | 中 | 締め処理はバッチで対応 |
| 人事 | 中 | 個人情報は要 RLS 検証 |
