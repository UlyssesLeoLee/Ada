## 1. 対象業務の概要

| 項目 | 内容 |
|---|---|
| 対象業務 | データ統合 ETL（Extract / Transform / Load）業務 |
| 業務範囲 | 複数データソース → 標準化 → 業務システム連携 |
| 対象ユーザー | データエンジニア、業務部門、IT 部門 |
| 業務頻度 | 日次バッチ（80%）、リアルタイム（20%） |
| 平均処理量 | 約 50 万件 / 日（参考値） |

## 2. アクターと役割

| アクター | 役割 | 責任 |
|---|---|---|
| データエンジニア | ETL 設計、実装、運用 | パイプライン構築、監視 |
| 業務部門 | 業務要件、検証 | 要件定義、受入テスト |
| IT 部門 | インフラ、統合 | 環境提供、認証 |
| マネージャー | 承認、優先度 | 業務承認、リソース配分 |

## 3. 主要業務フロー

### 3.1 データ取得（As-Is）

```
[業務システム A]                    [業務システム B]
   │                                    │
   │ CSV 出力（手動）                  │ DB 直読（専用 SQL）
   ▼                                    ▼

   │ マッピング定義                    │ Python 個別
   ▼                                    ▼

```

```
[中間 DB]
```

### 3.3 業務フロー詳細（BPMN 概要）

| # | タスク | アクター | システム | 所要時間 | 頻度 |
|---|---|---|---|---|---|
| 1 | データ要件定義 | 業務部門 | Excel | 2-3 日 | 案件毎 |
| 2 | ETL 設計 | データエンジニア | Informatica | 3-5 日 | 案件毎 |
| 3 | 実装 | データエンジニア | Informatica + Python | 1-2 週 | 案件毎 |
| 4 | 単体テスト | データエンジニア | 手動 | 1 日 | 案件毎 |
| 5 | 本番リリース | データエンジニア | 夜間手動 | 2 時間 | 月 2-3 件 |
| 6 | 運用監視 | データエンジニア | 手動ダッシュボード | 日次 | 日次 |
| 7 | 障害対応 | データエンジニア | 手動 | 数時間 | 月 1-2 件 |

## 4. 業務量 / 頻度

| 項目 | 値 |
|---|---|
| パイプライン総数 | 約 120 本 |
| 月間新規パイプライン | 約 8 本 |
| 月間変更パイプライン | 約 15 本 |
| 障害件数 | 月 1-2 件 |
| 復旧時間（MTTR） | 平均 4 時間 |
| 業務部門関与時間 | 案件あたり 平均 3 日 |

## 5. 業務上の課題

詳細は [DOC-UP-005 課題一覧](05-issue-list.md) 参照。

主要課題:

1. **専門知識必須**: ETL ツール（Informatica）のスキル保有者が社内に限られる
2. **手作業多発**: リリース・監視が手動
3. **属人化**: 特定エンジニアに依存
4. **リアルタイム性なし**: 全て夜次バッチ
5. **コスト**: Informatica ライセンス高
