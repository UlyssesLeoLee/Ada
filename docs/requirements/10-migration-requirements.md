## 1. 移行戦略

| MIG-ID | 戦略 | 用途 |
|---|---|---|
| MIG-01 | 段階移行 | パイロット → 全社 |
| MIG-02 | 並行稼働 | 旧システムと最大 30 日 |
| MIG-03 | Blue-Green | アプリ層 |
| MIG-04 | Canary | 一部テナントで先行 |
| MIG-05 | Big-bang | 緊急性高い場合のみ（推奨しない） |

## 2. 既存システムからの移行

### 2.1 既存資産

| 項目 | 内容 |
|---|---|
| ETL パイプライン | 約 120 本 |
| 中間 DB | PostgreSQL 12 → 16 へ |
| ダッシュボード | 約 100 シート |
| データ量 | 約 5 TB |

### 2.2 移行フェーズ

| フェーズ | 期間 | 内容 |
|---|---|---|
| パイロット | 2 ヶ月 | 主要 5 パイプラインを新システムへ |
| 部門展開 | 4 ヶ月 | 部門単位で順次 |
| 旧システム停止 | 1 ヶ月 | 並行稼働後、停止 |
| 合計 | 7 ヶ月 | |

### 2.3 移行順序

1. **データソース連携**（REST → REST 単純置換）
2. **変換ロジック**（Informatica → 新システム）
3. **エクスポート**（既存 DWH 維持）
4. **ダッシュボード**（Tableau 維持）

## 4. データ移行要件

| MIG-ID | 要件 | 詳細 |
|---|---|---|
| MIG-11 | データ整合性 | 100% |
| MIG-12 | 移行時間 | 5 TB / 8 時間以内 |
| MIG-13 | 暗号化 | 移行中も AES-256 |
| MIG-14 | 検証 | 件数 / checksum / サンプリング |
| MIG-15 | 監査 | 移行ログ 1 年保存 |
| MIG-16 | ロールバック | 旧 DB 即時復元可能 |
