## §1 背景 / 問題

QA 登録簿 §5.2 UN-P1-04: **QA-P01 1000 ノード 30fps 検証**、期限: **M-12 着手 -3 日**、Owner: **フロントエンド**。

[`crates/ada-canvas-ui/`](../../../crates/) (M-12) の Bevy フロントエンドで 1000 ノード 30fps 描画が性能要件だが、実機検証が未実施。

## §2 决策

**採用案**: **Bevy 0.14 + ECS 階層 culling + WASM SIMD + ベンチ公開**

- Bevy ECS 階層（親-子）で culling 最適化
- WASM SIMD (128-bit) で頂点変換高速化
- 目標: 1000 ノード / 30fps 持続 (Chrome / Safari / Firefox 最新版)
- ベンチ: `benches/canvas_render.rs` (wasm-pack)

## §3 選択肢と評価

### Option A: Bevy 0.14 + ECS + WASM SIMD ⭐ 推奨

- **优点**: 業界標準、ネイティブと WASM で同一コード
- **缺点**: ブラウザ間で SIMD 対応差
- **リスク**: Safari 16.4 以前で SIMD なし → graceful degrade
- **可逆性**: 中

### Option B: Three.js + 自前 ECS

- **优点**: ブラウザ対応広い、3D ライブラリ成熟
- **缺点**: Bevy との二重実装、コードベース分裂
- **リスク**: Bevy 機能活用不可
- **可逆性**: 低

### Option C: Canvas 2D + 自前最適化

- **优点**: シンプル、低スペック端末対応
- **缺点**: 1000 ノードで 30fps 困難
- **リスク**: 性能要件未達
- **可逆性**: 中

### Option D: WebGL 2 + 自前エンジン

- **优点**: 最高性能、柔軟
- **缺点**: 開発コスト膨大
- **リスク**: スケジュール破綻
- **可逆性**: 低

## §5 期限 / 触发条件

- **决策期限**: M-12 着手 -3 日
- **性能目標**:
  - 1000 ノード / 30fps 持続 (p95)
  - 初回ロード < 3s (光回線)
  - メモリ < 200MB
- **ブラウザ対象**: Chrome 120+, Firefox 120+, Safari 17+
- **反映先**:
  - `crates/ada-canvas-ui/benches/canvas_render.rs`
  - `docs/architecture/07-qa-register.md` §3.3 QA-P01
  - 性能レポート `docs/architecture/perf-reports/canvas-1000nodes.md`
- **再评估触发**:
  - 30fps 未達 → ノード数 culling 強化 / WebGPU 評価
  - Safari 対応問題 → SIMD degrade 確認

## §6 影响範囲 / リスク

- **影响模块**:
  - `crates/ada-canvas-ui/` (M-12)
  - Bevy プラグインシステム
  - イベント同期 (M-15 連動)
- **リスク评估**:
  - ブラウザ間差: Safari 性能劣、検証必要
  - GPU 差: 統合 GPU で 30fps 困難
  - WASM バンドルサイズ ([`p1-10`](./p1-10-WASM大小.md) と連動)
- **緩和策**:
  - ローエンド端末向けプリセット（"低性能モード" 設定）
  - FPS 監視 UI（dev mode のみ）
  - ベンチ結果は CI で自動更新
