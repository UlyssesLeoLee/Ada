## §1 背景 / 問題

QA 登録簿 §5.2 UN-P1-14: **QA-T06 セキュリティ浸透テスト計画**、期限: **M-13 着手 -3 日**、Owner: **セキュリティ**。

[`crates/ada-gateway/`](../../../crates/) (M-13) 公開前の浸透テスト計画（範囲、方法、合否基準、頻度）が未策定。

## §2 决策

**採用案**: **外部委託 年 1 回 + 内部四半期 + OWASP Top 10 + レッドチーム演習**

- **外部浸透テスト**: 年 1 回（M-13 GA 前必須）
- **内部自動スキャン**: 週次（OWASP ZAP, Trivy, Snyk）
- **対象範囲**:
  - OWASP Top 10 (Web)
  - OWASP API Security Top 10
  - 認証・認可バイパス
  - インジェクション (SQLi, XSS, CSRF, etc.)
  - 暗号・鍵管理（[`p0-06`](./p0-06-KMS.md), [`p0-07`](./p0-07-JWT.md)）
  - GDPR 削除フロー（[`p0-08`](./p0-08-GDPR.md)）
- **合否基準**: Critical/High 0 件、Medium < 5 件
- **レッドチーム**: 年 1 回、3 日間の標的型攻撃シナリオ

## §3 選択肢と評価

### Option A: 外部委託年 1 + 内部四半期 + レッドチーム年 1 ⭐ 推奨

- **优点**: 多層防御、客観的評価、最新脅威対応
- **缺点**: コスト高（$30K-100K/年）
- **リスク**: 外部委託の品質ばらつき
- **可逆性**: 中

### Option B: 内部のみ（自動スキャン）

- **优点**: 低コスト、持続的
- **缺点**: 内部視点のバイアス、高度攻撃見逃し
- **リスク**: 未知脆弱性
- **可逆性**: 高

### Option C: 外部委託のみ（年 1 回）

- **优点**: 客観的評価
- **缺点**: 頻度低、リリース毎検証不可
- **リスク**: リリース毎の脆弱性累積
- **可逆性**: 高

### Option D: バグバウンティ

- **优点**: 集合知、低コスト（成果報酬）
- **缺点**: Critical の対応遅延
- **リスク**: 報告のトリアージ負荷
- **可逆性**: 高

## §5 期限 / 触发条件

- **决策期限**: M-13 着手 -3 日
- **実施スケジュール**:
  - 外部浸透テスト: 2027-Q1 (v1.0 GA 前)
  - レッドチーム: 2027-Q2
  - 内部自動スキャン: 週次（CI 統合）
  - 緊急パッチ: Critical 検出時 24 時間以内対応
- **反映先**:
  - `docs/architecture/07-qa-register.md` §3.4 QA-T06
  - `docs/operations/10-pentest-plan.md` (実施計画書)
  - CI 統合 `.github/workflows/security-scan.yml`
  - 修正 SLA `docs/operations/11-vuln-sla.md`
- **再评估触发**:
  - Critical/High 検出 → 即時対応 + 再テスト
  - コンプラ監査指摘 → 計画見直し

## §6 影响範囲 / リスク

- **影响模块**:
  - 全 16 crate（特に M-13 Gateway, M-10 Tenant, M-15 Event Bus）
  - KMS / JWT 鍵管理（[`p0-06`](./p0-06-KMS.md), [`p0-07`](./p0-07-JWT.md)）
  - GDPR 削除フロー（[`p0-08`](./p0-08-GDPR.md)）
  - バックアップ（[`p0-10`](./p0-10-Backup.md)）
- **リスク评估**:
  - 修正 SLA 未達: Critical 24h / High 7d / Medium 30d
  - 委託先品質: 契約に評価指標 + 再委託条件
  - 修正による機能破壊: ステージングで全テスト
- **緩和策**:
  - 修正チケットの優先度自動設定（P0 緊急）
  - 委託先は CREST / OSCP 認定
  - 修正後 7 日以内再スキャン
