## §1 背景 / 問題

QA 登録簿 §5.2 UN-P1-05: **QA-P04 100 ノードクラスタ検証環境**、期限: **M-16 着手 -7 日**、Owner: **DevOps + SRE**。

[`crates/ada-orchestrator/`](../../../crates/) (M-16) のクラスタオーケストレータで 100 ノード規模での動作検証環境（k8s / Nomad 等）が未構築。

## §2 决策

**採用案**: **k3s + Terraform 自動構築 + GitHub Actions 夜間 E2E**

- 100 ノード規模: k3s (軽量 k8s) で 1 master + 100 worker
- IaC: Terraform + Ansible でフル自動構築
- E2E: GitHub Actions nightly 100 ノード起動 → キャンバス操作 → 性能測定

## §3 選択肢と評価

### Option A: k3s + Terraform 自動構築 ⭐ 推奨

- **优点**: 軽量、起動 30 秒、CI 統合容易、コスト低
- **缺点**: 100 ノード = 単一 VM で 100 プロセス = 性能不正確
- **リスク**: クラウド 100 VM コスト高（$50-100/h）
- **可逆性**: 中

### Option B: EKS / GKE マネージド

- **优点**: 本番同等、自動スケール
- **缺点**: コスト高、100 ノード常時起動は $
- **リスク**: クラウド障害
- **可逆性**: 中

### Option C: Docker Swarm 自前

- **优点**: シンプル、起動速い
- **缺点**: エコシステム弱、本番採用少
- **リスク**: 100 ノードでの実績少
- **可逆性**: 中

### Option D: 物理 / ベアメタル 100 台

- **优点**: 性能正確
- **缺点**: コスト膨大、場所・電源・運用
- **リスク**: 投資回収不能
- **可逆性**: 低

## §5 期限 / 触发条件

- **决策期限**: M-16 着手 -7 日
- **環境目標**:
  - 100 ノード起動時間: < 10 分
  - E2E 1 ラウンド: < 30 分
  - コスト: 月 $1,000 以内
- **反映先**:
  - `terraform/cluster/100node/` (IaC)
  - `.github/workflows/nightly-100node-e2e.yml`
  - `docs/architecture/07-qa-register.md` §3.3 QA-P04
  - 運用 Runbook `docs/operations/06-cluster-100node.md`
- **再评估触发**:
  - コスト超過 → 夜間のみ起動へ
  - E2E 不安定 → 30 ノードに縮小

## §6 影响範囲 / リスク

- **影响模块**:
  - `crates/ada-orchestrator/` (M-16)
  - クラスタ運用全般
  - CI/CD パイプライン
- **リスク评估**:
  - コスト管理: 夜間 + 週末停止で 70% 削減
  - クラウド quota: 100 ノードは要申請
  - テスト不安定: フレーク検出 + リトライ
- **緩和策**:
  - GitHub Actions の self-hosted runner で 1 台占有
  - 失敗時の自動停止スクリプト
  - 週次コストレビュー
