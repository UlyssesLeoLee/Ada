## §1 背景 / 問題

QA 登録簿 §5.2 UN-P1-12: **QA-M05 DB マイグレーション戦略**、期限: **M-10 着手 -3 日**、Owner: **DBA + DevOps**。

[`crates/ada-tenant-middleware/`](../../../crates/) (M-10) の DB マイグレーションがアドホック。`expand-contract pattern` を用いた安全なマイグレーション戦略が文書化されていない。

## §2 决策

**採用案**: **expand-contract pattern (3 段) + sqlx-migrate + CI ゲート + ロールバック必須**

```sql
-- Phase 1: expand（追加）
ALTER TABLE canvas ADD COLUMN new_owner_name VARCHAR(255);
-- アプリ v1.1: 新カラムに書込、旧カラムは read で並走

-- Phase 2: migrate（データ移行）
UPDATE canvas SET new_owner_name = owner_name WHERE new_owner_name IS NULL;
-- アプリ v1.2: 旧カラム read のみ

-- Phase 3: contract（削除）
ALTER TABLE canvas DROP COLUMN owner_name;
-- アプリ v1.3: 旧カラム参照禁止
```

- 各 Phase 間に最低 1 週間の並走期間
- ロールバック: 各 Phase で `down.sql` 必須
- CI: `--check` フラグで `sqlx migrate run` テスト

## §3 選択肢と評価

### Option A: expand-contract 3 段 + sqlx-migrate + ロールバック ⭐ 推奨

- **优点**: 業界標準（Stripe, GitHub 採用）、ダウンタイム 0、安全
- **缺点**: マイグレーション 3 倍のコスト、複雑
- **リスク**: Phase 2 でバックフィル失敗
- **可逆性**: 高（各 Phase でロールバック可）

### Option B: 即時 ALTER（破壊的）

- **优点**: シンプル、速い
- **缺点**: ダウンタイム、ロールバック困難
- **リスク**: 本番事故時の被害大
- **可逆性**: 低

### Option C: Blue-Green DB スワップ

- **优点**: 切替瞬時、ロールバック即時
- **缺点**: コスト 2 倍、ストレージ 2 倍
- **リスク**: 同期ラグ、データ不整合
- **可逆性**: 高

### Option D: 論理レプリケーション + スクリプト

- **优点**: 柔軟
- **缺点**: 運用複雑、ケース毎カスタム
- **リスク**: スクリプト バグ
- **可逆性**: 中

- **リスク评估**:
  - バックフィル長時間: チャンク分割必須
  - アプリ v1.1/v1.2 並走の同期ズレ: 読み書き経路のテスト
  - ロールバック不備: dry-run + staging で検証
- **緩和策**:
  - 各マイグレーションで `EXPLAIN` 確認
  - 大量 UPDATE はバッチ + sleep
  - 本番適用はメンテナンスウィンドウ外
