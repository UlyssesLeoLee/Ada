# v0.5.0 真接入 Roadmap

> Closes the deferred items from v0.4.0 (`auth-billing-arch.md`):
> casbin 2.x, Stripe sandbox end-to-end, real IdP wire-format deps.
> Three-worker parallel dispatch with disjoint ownership.

## 1. worker-K: casbin 2.x 真接入 (`crates/ada-rbac-casbin`)

### Why deferred until v0.5.0

In v0.4.0 the `Enforcer` is hand-rolled. The `crates/ada-rbac-casbin/policies/`
directory already carries the CSV-shaped policy file and the `model.conf`
declaration in casbin's native syntax, so the swap-in is mechanical.

### v0.5.0 contract

| Item | Contract |
|------|----------|
| Public API | unchanged — `Enforcer::from_m11`, `enforce`, `enforce_typed`, `AdminApi`, `HotReload::reload_now` keep their signatures |
| Internal | `casbin::Enforcer::new(model, adapter)` with a `FileAdapter` pointing at the bundled CSV |
| Postgres overrides | `AdminApi::add_policy` writes a row into `rbac_policy_override`; `Enforcer::reload_now` rebuilds against the merged view |
| File watcher | `HotReload::spawn_watcher` returns a real `notify::RecommendedWatcher` watching the policy dir |
| Tests | 6 smoke tests + 1 integration test against a Postgres-backed adapter (skipped in CI without DB) |

### Out of scope (deferred)

- Casbin decision logs (v0.6.0).
- Adapter migration to `sea-orm` (v0.6.0).

## 2. worker-L: Stripe sandbox 端到端 (`crates/ada-billing`)

### Why deferred to v0.5.0

The v0.4.0 webhook handler and customer/portal services use the
`stripe-rust` 0.12 dep's `Webhook::construct_event` only as a
shape reference. The HMAC verification is hand-rolled because
`crypto-mac 0.6` (transitive via `stripe-rust 0.12`) is yanked.

### v0.5.0 contract

| Item | Contract |
|------|----------|
| Webhook verification | hand-rolled HMAC-SHA256 (already in v0.4.0) + RFC 6238 TOTP compatibility tests |
| Sandbox E2E | `tests/sandbox_e2e.rs` runs against `https://api.stripe.com/v1` with `STRIPE_SECRET_KEY=sk_test_…` injected via env (test-only). Skipped when env not set. |
| Missing docs | bring 49 warnings down to ≤ 5; add module-level doc + doc comments on all public functions |
| Idempotency table | in-process `HashSet` stays; production wiring uses Postgres in v0.6.0 |

### CI gate

`mobile-build.yml`'s `sandbox-e2e` job runs only on `workflow_dispatch`
inputs `sandbox=true` + env `STRIPE_SECRET_KEY` set (avoids accidental
live charges).

## 3. worker-M: ada-identity 真 wire-format deps (`crates/ada-identity`)

### Why deferred to v0.4.0

`openidconnect`, `samael`, `webauthn-rs` (0.10 not published — latest
is 0.6.x), `totp-rs` all carry transitive C deps (xmlsec) or pre-1.0
crate churn. The v0.4.0 skeleton ships the state machine + RFC
shapes only.

### v0.5.0 contract

| Module | Real dep | v0.5.0 swap |
|--------|----------|-------------|
| `oidc` | `openidconnect = "3"` | replace PKCE verifier stub with `CoreClient::exchange_code` |
| `saml` | `samael = "0.0.22"` | `AuthnRequestBuilder` for outgoing, `ResponseParser` for incoming, signature via `samael::signature` |
| `webauthn` | `webauthn-rs = "0.6"` | `WebauthnCore` state machine, `CreationChallengeResponse` / `RequestChallengeResponse` |
| `totp` | `totp-rs = "5"` | `Secret::generate()`, `TwoFactorAuth::verify()` with RFC 6238 test vectors |

### Test posture

- OIDC: wiremock-mock IdP; the v0.4.0 happy-path test extends.
- SAML: parse a hand-built SAMLResponse.xml fixture; signature
  verification requires xmlsec — gate the signature test on
  `SAML_IDP_CERT_PEM` env.
- WebAuthn: in-process virtual authenticator (`soft-webauthn`); the
  registration ceremony is exercised round-trip.
- TOTP: RFC 6238 Appendix D test vectors are mandatory.
