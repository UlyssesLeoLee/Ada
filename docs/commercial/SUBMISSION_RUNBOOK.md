# Submission Runbook — App Store & Google Play

Authoritative checklist for getting gm-console Mobile shipped to Apple App Store and
Google Play. Companion to `COMPLIANCE_SELFCHECK.md` (the latter is the audit; this is
the operation).

## Pre-submission (every release)

1. CI green: `mobile-build.yml` job "sign-and-pack-{ios,android}" produced artifacts.
2. `compliance-selfcheck.yml` (worker-F target) reports zero findings.
3. `flutter version` matches `apps/gm-console-app/.flutter-version` (3.24.5).
4. Marketing version (`pubspec.yaml`) and `Info.plist` `MARKETING_VERSION` agree on
   `0.X.Y`.
5. `docs/CHANGELOG.md` has a top-of-file entry referencing the version being shipped.
6. Screenshots in `release-artifacts/screens-*.png` (rendered by
   `apps/gm-console-web/scripts/render-screenshots.js`) match the binary's
   brand screen colors.

## Apple App Store Connect lane

1. Sign in to https://appstoreconnect.apple.com.
2. My Apps → **gm-console** → "+ Version or Platform".
3. Version number: `0.X.Y (X)`. Copyright: `Ada Project Team, 2026`.
4. Upload `release-artifacts/gm-console-iOS-Release.ipa` via Xcode → Organizer or
   `xcrun altool --upload-package`.
5. **App Information**:
   - Privacy Policy URL: `https://ada.kanvas.dev/privacy`
   - Subtitle (≤30 char): runbook must read "Pipe · Monitor · Recover"
6. **Pricing and Availability**:
   - Free
   - Availability: All territories
7. **App Privacy**:
   - Click "Edit" → import `docs/commercial/apple-app-privacy.json` answers.
8. **Build**:
   - Select the uploaded build.
   - Export Compliance: click "Manage" → "Built-in cryptography only" → enter
     `https://github.com/UlyssesLeoLee/Ada/blob/main/LICENSE` for compliance code.
     Pin answer to **"Yes (uses exempt cryptography)"** — our TLS is exempt.
9. **Screenshots and App Previews**:
   - 6.5" iPhone: 1242×2688 (min 3, max 10)
   - 6.7" iPhone: 1290×2796 (min 3, max 10)
   - 12.9" iPad: 2048×2732 if iPad support enabled
   - First-frame match: capture order MUST match rendering order in
     `apps/gm-console-web/dist/screenshots/INDEX.md`.
10. **Version Release**:
    - "Manually release this version" → recommended for v0.3.0.
    - Phased Release is for later.
11. Submit for Review.

## Google Play Console lane

1. Sign in to https://play.google.com/console.
2. **gm-console** → "Internal testing" → "Create new release".
3. Upload `release-artifacts/gm-console.aab` (App Bundle).
4. **Release notes**: pull from `docs/CHANGELOG.md`.
5. **Data safety**: import `docs/commercial/google-play-data-safety.json` answers.
   - Cross-check that "Account info" → "App functionality" matches actual flows.
6. **App content**:
   - Privacy policy: `https://ada.kanvas.dev/privacy`
   - Ads: NO.
   - App access: app is fully functional — explain screen flow.
   - Government apps: NO.
   - Financial features: NO.
   - Health apps: NO.
7. **Store listing**:
   - Short description (≤80 char): "Run, monitor, and recover Ada data pipelines from your phone."
   - Full description: `docs/commercial/STORE_LISTING.md` (English source).
   - Localized variants: ja + zh-Hans (`STORE_LISTING_ja.md`, `STORE_LISTING_zh-Hans.md`)
8. **Graphics**:
   - App icon: `release-artifacts/play-store-512.png` (Play marketing)
   - Feature graphic: 1024×500 PNG, generated by `apps/gm-console-app/brand/icon-gen.js`
     with `--feature-graphic` flag (post-v0.3.0 extension).
9. **Release**:
   - Rollout: 1% → 5% → 20% → 100% over 7 days.
   - Staged: enable for Opt-in Pro users first.

## Rollback / revocation playbooks

- **App Store**: in App Store Connect → "Remove from Sale" blocks future downloads.
  The build stays installed for users who already have it.
- **Google Play**: Play Console → "Disable / Unpublish" gives the same effect.
- **Push credentials revoked**: rotate the p12 OR re-issue the upload keystore;
  trigger an emergency release with `--no-push` guard and re-push the patch.
- **Brand assets drift**: re-run `icon-gen.js` from the locked
  `icon-source.svg`. New raster outputs flow into the next release cycle only —
  no hot-swap.

## Crisis escalation

- **P0 — leaked signing key**: rotate + revoke immediately; follow SIGNING_RUNBOOK.md
  §incident 1. All-hands → DDD Review.
- **P1 — privacy disclosure mismatch**: file at top of `docs/commercial/INCIDENT_*`
  and re-submit corrected nutrition / data-safety JSON via App Privacy re-edit
  (Apple) or "Policy and programs" path (Google).
- **P2 — broken UI**: roll out emergency hotfix via phased release + A/B feature flag.

## Don't

- Do NOT push under Apple's old "still using deprecated cryptography" decision.
  Always check Export Compliance first.
- Do NOT list yourself as the seller of an Enterprise Program — stay on Apple
  Developer Program (App Store) or Apple Developer Enterprise Program only when
  distributing purely to internal employees.
- Do NOT skip the deferred-permissions rationale on the App Privacy form. Apple
  reviews the "linked to user" answer.
